# AIC8800D80 Wi-Fi and Bluetooth on Fedora Kinoite (akmods)

This repository installs the out-of-tree **AIC8800D80** driver on Fedora Kinoite
using **akmods**. The kernel module is compiled and signed by akmods for every
kernel, and the built module is applied to the system image with `rpm-ostree`.
A kernel update is handled automatically: when the system boots into the new kernel,
the module for that kernel is built, signed and applied.

The driver works with Secure Boot enabled or disabled. With Secure Boot enabled, the
signing certificate must be trusted by UEFI (enrolled in the `db` list or in MOK).

## Contents

- `aic8800-kinoite.sh`: key import, build, install, status and removal commands.
- `aic8800d80-kmod.spec`: kmod spec used by akmods. It compiles the modules and signs
  them with the key in `/etc/pki/akmods`.
- `akmod-aic8800d80.spec`: source-only package (noarch, no scripts). It installs the
  kmod source RPM to `/usr/src/akmods/`, where akmods finds it.
- `aic8800d80-firmware.spec`: firmware package (firmware, udev rules, usb_modeswitch).
- `.gitignore`: keeps signing keys and build artifacts out of Git.

## How it works

1. **Source.** `build` downloads the driver source from the fork
   [`codebyallan/aic8800d80`](https://github.com/codebyallan/aic8800d80), branch `main`,
   at the current head of that branch.
2. **Packages.** `build` creates three RPMs in `~/rpmbuild/RPMS/`: the firmware package,
   the source package for akmods, and the kmod source RPM that the source package ships.
3. **Layering.** `install` layers the firmware package and the source package with
   `rpm-ostree`. Neither package has scripts, so nothing is compiled during installation.
4. **Build and apply.** `aic8800-kmod-sync.service` runs at boot. If the kmod for the
   running kernel is missing, it runs `akmods` on the host. akmods builds and signs the
   module, and the service applies the resulting kmod RPM with `rpm-ostree`. The change
   takes effect immediately with `--apply-live`, or at the next boot if that is not
   possible.
5. **Hot-plug.** A udev rule starts `aic8800-reload.service` when the dongle is
   re-plugged. If Wi-Fi is not usable, the helper reloads the driver.

## Supported hardware

USB device `a69c:8d80` (`AIC Wlan`), a combined Wi-Fi and Bluetooth adapter.
Bluetooth uses the standard `btusb` driver once the firmware is loaded.

Other AIC8800 variants are not tested here. The firmware package includes all firmware
variants from upstream, but the hot-plug helper only covers `8d80`.

## Driver source

By default the script builds from the fork
[`codebyallan/aic8800d80`](https://github.com/codebyallan/aic8800d80), branch `main`.

Choose the branch for your hardware revision. With the dongle connected, run:

```bash
sudo dmesg | grep -i chip_mcu_id
```

- `chip_mcu_id=0`, or the line is missing: use `main` (default).
- `chip_mcu_id=1`: use `legacy-mcu1`. It initializes Bluetooth through the standard
  `btusb` driver and avoids the firmware upload timeout at `0x170400`.

```bash
BRANCH=legacy-mcu1 bash aic8800-fedora-kinoite.sh build
```

To pin a specific commit:

```bash
COMMIT=<hash> bash aic8800-fedora-kinoite.sh build
```

If you have firmware copied manually into `/lib/firmware/aic8800*` from an older
installation, remove it before installing, so that firmware from a different version is
not used:

```bash
sudo rm -rf /lib/firmware/aic8800*
```

## Requirements

- Fedora Kinoite (tested on Fedora 45, kernel 7.3).
- These packages must be layered on the host. Install any that are missing with
  `sudo rpm-ostree install <package>` and reboot:
  `akmods`, `kernel-devel`, `gcc`, `make`, `elfutils-libelf-devel`.
- `toolbox`, `git` and `podman`, which ship with Kinoite.
- Internet access for `build`, to query the repository and download the source.

## Signing key

The key lives in one fixed location:

- `~/.aic8800-keys/db/db.key` (private key, mode 0600)
- `~/.aic8800-keys/db/db.pem` (certificate)
- `~/.aic8800-keys/db/db.der` (DER form of the certificate, generated by `keys`)

The `keys` command:

1. **Imports** the pair when you pass the folder with `KEY_DIR`. The source folder is not
   changed.
2. Uses the existing pair in `~/.aic8800-keys/db/`, or **generates** a new one there if
   none exists.
3. **Installs** the key for akmods at `/etc/pki/akmods/` (certificate `0644`, private key
   `root:akmods` `0640`). It also masks `akmods-keygen`, so Fedora does not generate
   another key over yours.
4. Checks UEFI enrollment and runs `mokutil --import` if the certificate is not trusted.

```bash
KEY_DIR=/path/to/your/keys/db bash aic8800-fedora-kinoite.sh keys
```

Keep `~/.aic8800-keys` in place. The key is read from there when you rebuild, and copied
to `/etc/pki/akmods/` by `keys`.

A key used for Secure Boot policy (for example, the PK or KEK from `sbctl`) should not sit
in a synced or indexed folder. The `db` key from `sbctl` can be used here, but it can also
sign any boot component that your firmware trusts, so treat it with the same care as a
password.

If Secure Boot is enabled and the certificate is not enrolled, enter the one-time password
you set on the blue MOK Manager screen at the next boot: choose **Enroll MOK**, confirm, and
type the password. This is needed once per certificate.

## Usage

Run the commands from the folder that contains the script and the spec files:

```bash
cd ~/path/to/aic8800-kinoite
chmod +x aic8800-fedora-kinoite.sh
```

| Command   | Description |
|-----------|-------------|
| `keys`    | Imports or finds the key pair, installs it for akmods, and checks UEFI enrollment. |
| `build`   | Resolves the source commit, downloads the source (once), and builds the three RPMs in the `aic8800-build` toolbox. |
| `install` | Removes older packages, layers the firmware and source packages with `rpm-ostree`, writes the services, and starts the apply service. Reboots after 15 seconds. |
| `all`     | Runs `keys`, `build` and `install` in sequence. |
| `status`  | Shows the packages, the kmod for the running kernel, the key, the loaded module, its signer, the Wi-Fi interface and the apply service. |
| `remove`  | Removes the services and the layered packages, and cleans up the akmods cache. Your keys in `~/.aic8800-keys` are kept. |

To install without rebooting immediately, set `AIC_NO_REBOOT=1`:

```bash
AIC_NO_REBOOT=1 bash aic8800-fedora-kinoite.sh install
```

### First installation

```bash
KEY_DIR=/path/to/your/keys/db bash aic8800-fedora-kinoite.sh keys
bash aic8800-fedora-kinoite.sh build
AIC_NO_REBOOT=1 bash aic8800-fedora-kinoite.sh install
sudo systemctl reboot
```

After the reboot, check the result:

```bash
bash aic8800-fedora-kinoite.sh status
sudo journalctl -u aic8800-kmod-sync.service -b --no-pager | tail -15
```

`status` should show `kmod for this kernel: installed`, `module loaded: 1`, a `wlan*`
interface, and `module signed by` with the name of your certificate.

## Kernel updates

No action is required. When the system boots into a new kernel:

1. `akmods.service` (from Fedora) and `aic8800-kmod-sync.service` see that the kmod for
   the running kernel is missing.
2. akmods builds and signs the module against `/usr/src/kernels/<kernel>`.
3. The service applies the new kmod RPM with `rpm-ostree` and removes kmods built for
   other kernels in the same transaction.

Keep `kernel-devel` in the layered package list. It is required for the build, and it is
updated together with the kernel.

## Hot-plug behavior

When the dongle is connected, the udev rule starts `aic8800-reload.service`. If Wi-Fi is not
usable, the helper:

1. Removes `aic8800_fdrv` and `aic_load_fw` with `rmmod`.
2. Runs the apply service again, which loads the driver.
3. Restarts `wpa_supplicant`, then `NetworkManager`.
4. Checks the result with a real scan (`iw dev <wl*> scan`).

A 60-second guard stops the helper from being triggered by the USB events it causes.

```bash
journalctl -u aic8800-reload.service -b --no-pager | tail -10
nmcli device status
```

## Known limitations

- **akmods output is hidden by the service.** The apply service runs `akmods` quietly. If a
  build fails, run `sudo akmods --force --kernels $(uname -r)` by hand to see the error.
- **The yum error is expected.** akmods tries to install its RPM with `yum`, which does not
  exist on Kinoite. The service applies the RPM with `rpm-ostree` instead, so the message
  `Could not install newly built RPMs` does not mean the build failed.
- **Hot-plug is not reliable on its own.** After a re-plug, the firmware can fail to open
  with `ENOENT` (`errno=-2`). The helper recovers in most cases. If it does not, reboot with
  the dongle connected.
- **The helper depends on `wpa_supplicant` and NetworkManager.** If they are not running,
  Wi-Fi stays unavailable even though the driver is loaded.
- **Upstream bug.** The hot-plug failure is in the driver's firmware loading. The logs and the
  commit in use are the information needed to report it upstream.

## Troubleshooting

**`No akmod packages found` from akmods.**
akmods looks for a `akmod-aic8800d80` package and the `aic8800d80-kmod.latest` link in
`/usr/src/akmods/`. Check:

```bash
rpm -q akmod-aic8800d80
ls -la /usr/src/akmods/
```

**`Key was rejected by service` or `Loading of unsigned module is rejected`.**
The module is not signed by a certificate the kernel trusts. Check:

```bash
mokutil --test-key /etc/pki/akmods/certs/public_key.der
modinfo -F signer aic8800_fdrv
```

The first command should answer `is already enrolled`. The second should show your
certificate name.

**`ERROR: no kmod built` in the journal.**
Run the build by hand and read the output:

```bash
sudo akmods --force --kernels $(uname -r) 2>&1 | tail -40
sudo tail -40 /var/cache/akmods/aic8800d80/*.failed.log
```

**`rpm-ostreed` aborts during `install`.**
Restart the daemon and run the command again:

```bash
sudo systemctl restart rpm-ostreed
```

**`wpa_supplicant couldn't grab this interface`.**

```bash
sudo systemctl restart wpa_supplicant
sudo systemctl restart NetworkManager
```

**`file failed to open` or `errno=-2` after a re-plug.**
This is the upstream hot-plug issue. Reboot with the dongle connected.

## Uninstall

```bash
bash aic8800-fedora-kinoite.sh remove
sudo systemctl reboot
```

`remove` keeps your keys in `~/.aic8800-keys`. To remove the certificate from MOK:

```bash
sudo mokutil --delete ~/.aic8800-keys/db/db.der
sudo systemctl reboot
```
